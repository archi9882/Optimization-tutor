# 遊戲化設計依據

**狀態：** 研究摘要，供設計決策參考。

**限制：** 研究時無法直接開啟來源網頁，下列引用都來自搜尋結果摘要，**全部待查證**。在頁面或 README 引用任何一項之前，必須先開原文確認。

## 原則

- **獎勵技能，不獎勵完成：** 為完成而給的獎勵可能削弱內在動機（Deci、Koestner、Ryan 1999 的統合分析，待查證）。開頁面不給分。
- **精熟度要經得起時間：** 隔天以後的複習通過，才算熟練。
- **練習要混合：** 分類練習在當下表現較好，混合練習在一週後表現較好（Rohrer、Taylor 2007，待查證）。
- **不做每日連續打卡：** 改用每週目標，並允許休息週，避免斷掉連續紀錄造成焦慮。
- **技能樹不上鎖：** 前置條件只提示、不阻擋，方便求職者直接跳到職缺要求的演算法。
- **不放任何未經查證的成效數字。**

## 機制與實作順序

| 階段 | 機制 | 說明 |
|---|---|---|
| MVP | 進度資料層 | 單一 localStorage 鍵 `ot.progress.v1`，提供匯出、匯入，並有版本號 |
| MVP | 回想卡 | 面試追問先作答，再展開答案，自評 忘了／模糊／會 |
| MVP | 預測題 | 動畫播放前先選預測，播放後對照實際結果；答案以程式實測決定 |
| MVP | 評分回饋 | 指出哪一層、哪裡錯，並連到對應的推導 |
| 核心循環 | 間隔複習 | Leitner 盒，間隔 1、2、7、21、60 天，首頁顯示「今日複習」 |
| 核心循環 | 精熟度 | 看過 → 熟悉（練習三層全過）→ 熟練（隔 2 天以上複習通過，且回想卡七成以上答「會」）→ 精通（模擬面試答對）；由紀錄即時計算，答錯會退回 |
| 核心循環 | 每週目標 | 學習者自訂每週要完成的量 |
| 後設遊戲 | 技能樹 | 依目錄的 `after` 關係畫成圖，節點顏色代表精熟度 |
| 後設遊戲 | 模擬面試 | 5～8 題混合題：情境選方法、失效情境、挖空 |
| 後設遊戲 | 分級練習 | 排序虛擬碼 → 挖空 → 挖更多 |
| 打磨 | 新手引導 | 選目標職位，加上程度測驗 |
| 打磨 | 個人紀錄 | 只和自己比，不設排行榜 |
